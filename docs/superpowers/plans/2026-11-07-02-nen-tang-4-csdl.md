# Kế hoạch 2 – Nền tảng kết nối 4 CSDL

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Backend kết nối được MongoDB, Cassandra, Neo4j, Redis; có trang kiểm tra trạng thái 4 CSDL, bộ sinh mã chứng từ, lớp `RedisSafe` và hàng đợi đồng bộ `sync_queue` chạy được. Chưa có nghiệp vụ.

**Architecture:** Mỗi CSDL có một lớp cấu hình riêng trong `config/`. Kết nối Cassandra và Neo4j tạo lười (lazy), nên ứng dụng vẫn khởi động khi một CSDL phụ đang tắt (NFR-09). Schema Cassandra, constraint Neo4j và index MongoDB được tạo lúc khởi động nếu còn thiếu. `sync_queue` có cơ chế xử lý chung; các handler ghi Cassandra/Neo4j cụ thể được thêm ở kế hoạch 5, 7, 8.

**Tech Stack:** Spring Boot 4.1.1, `spring-boot-starter-data-mongodb`, `spring-boot-starter-data-redis`, `org.neo4j.driver:neo4j-java-driver` (phiên bản do Boot quản lý), `com.datastax.oss:java-driver-core` 4.17 (đang có), JUnit 5 + Mockito.

**Spec:** `docs/superpowers/specs/2026-11-07-nosql-redesign-design.md` mục 3, 5.1 (`counters`, `sync_queue`), 6, 7, 8, 9, 19.5. SRS v2.0: NFR-05, NFR-09, NFR-11, mục 2.5–2.6.

## Global Constraints

- Không commit bí mật. `.env` ở thư mục gốc; bundle Astra ở `secrets/`.
- Mã chứng từ theo SRS v2.0: `HD261107-0042` (đơn), `PN261107-0001` (phiếu nhập), `L261107-0003` (lô), `PT261108-0001` (phiếu trả). Dạng `<tiền tố><yyMMdd>-<4 số>`, ngày theo `Asia/Ho_Chi_Minh`. Spec mục 5.2 ghi `HD20261107`; theo SRS là `yyMMdd`.
- Bộ đếm nằm ở MongoDB `counters`, không dùng Redis.
- Mọi kết nối dùng TLS khi chạy cloud (Atlas `mongodb+srv`, Astra bundle, Aura `neo4j+s`, Redis `rediss`).
- `./mvnw test` phải chạy được khi **không** có CSDL nào: test cần CSDL thật gắn tag `cloud` và bị loại mặc định.
- MongoDB phải là replica set (Atlas M0 là replica set). MongoDB cài máy ở chế độ standalone **không có transaction**.

## Review Focus

- Khởi động khi Neo4j hoặc Cassandra tắt: ứng dụng vẫn lên, `/api/health/datastores` báo `DOWN` cho CSDL đó, không treo quá 5 giây mỗi CSDL.

- Job đồng bộ không lấy bản ghi đang được xử lý ngay sau commit (chỉ lấy bản ghi `PENDING` cũ hơn 30 giây).

### Task 6: Hàng đợi đồng bộ `sync_queue`

**Files:**
- Create: `sync/SyncTask.java` (document), `sync/SyncStatus.java`, `sync/SyncHandler.java`, `sync/SyncQueue.java`, `sync/SyncService.java`, `sync/SyncJob.java`, `sync/SyncController.java`, `config/AsyncConfig.java`
- Test: `sync/SyncServiceTest.java`

**Interfaces:**
- `@Document("sync_queue") SyncTask { String id; String type; String refId; Document payload; SyncStatus status; int attempts; String lastError; Instant createdAt; Instant doneAt; String ownerId; }` – `ownerId` là thu ngân tạo bản ghi, dùng cho chốt ca (FR-12).
- `enum SyncStatus { PENDING, DONE, FAILED }`
- `interface SyncHandler { String type(); void apply(SyncTask task); }` – có thể có nhiều handler cùng `type` (ví dụ `ORDER_CREATED` có handler Cassandra và handler Neo4j); mỗi handler phải ghi lặp an toàn.
- `SyncQueue.enqueue(String type, String refId, Document payload, String ownerId): SyncTask` – gọi **bên trong** transaction nghiệp vụ; đăng ký `TransactionSynchronization.afterCommit` để gọi `SyncService.processAsync(id)`.
- `SyncService.process(String id)`: đọc bản ghi; không phải `PENDING` thì bỏ qua. Chạy mọi handler của `type`; tất cả thành công → `DONE`, `doneAt`. Một handler lỗi → `attempts+1`, `lastError`; đạt `max-attempts` → `FAILED`. Không có handler nào cho `type` → `FAILED` với `lastError = "no handler"`.
- `SyncService.processPending(Instant olderThan, int limit)`, `SyncService.processPendingForOwner(String ownerId)` (chốt ca gọi), `SyncService.retryFailed(): int` (đặt `FAILED` về `PENDING`, `attempts = 0`).
- `SyncJob`: `@Scheduled(fixedDelayString = "${app.sync.interval-ms}")`, chỉ chạy khi `app.sync.enabled=true`; xử lý bản ghi `PENDING` cũ hơn `min-age-seconds`, mỗi lần tối đa 200.
- `GET /api/admin/sync/status` → `{pending, failed, oldestPendingAt, recentFailures[≤10]}`; `POST /api/admin/sync/retry` → `{reset: n}`. Chỉ `ADMIN`.

- [x] **Step 1:** Test thất bại `SyncServiceTest` (Mockito, `MongoTemplate` giả lập): thành công → `DONE`; handler ném lỗi → `PENDING`, `attempts=1`; lỗi lần thứ 10 → `FAILED`; không có handler → `FAILED`; bản ghi đã `DONE` → handler không được gọi; hai handler cùng type, một lỗi → không `DONE`.
- [x] **Step 2:** Viết các lớp → PASS.
- [x] **Step 3:** `AsyncConfig`: executor `syncExecutor` 2–4 luồng, hàng đợi 500. `SyncQueue` gọi thẳng executor sau commit thay cho `@Async` (tránh lỗi tự gọi qua proxy).

## Chuẩn bị (chủ dự án làm, trước Task 8)

| CSDL | Việc cần làm | Biến trong `.env` |
|---|---|---|
| MongoDB Atlas | Tạo cluster M0, user database, cho phép IP máy mình (hoặc `0.0.0.0/0` khi demo) | `MONGODB_URI=mongodb+srv://...`, `MONGODB_DATABASE=supermarket` |
| Astra DB | Dùng database đang có; tạo keyspace `supermarket` trên giao diện; tải lại secure bundle nếu hết hạn | `CASSANDRA_MODE=ASTRA`, `ASTRA_SECURE_BUNDLE=../secrets/secure-connect-supermarket-bigdata.zip`, `APPLICATION_TOKEN`, `CASSANDRA_KEYSPACE=supermarket` |
| Neo4j AuraDB Free | Tạo instance, lưu mật khẩu hiện một lần lúc tạo | `NEO4J_URI=neo4j+s://...`, `NEO4J_USERNAME`, `NEO4J_PASSWORD` |
| Redis Cloud / Upstash | Tạo database free, bật TLS | `REDIS_URL=rediss://default:...@...` |

Xóa các biến cũ không còn dùng trong `.env`: `DB_*`, `DRILL_*`, `ASTRA_ENABLED`, `ASTRA_KEYSPACE`, `LOCAL_BOOTSTRAP`, `SIMULATION_*`, `SYNC_BATCH_SIZE`.
